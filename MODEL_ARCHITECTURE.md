# Архитектура модели прогнозирования волатильности (As-is)

Документация описывает текущее состояние пайплайна машинного обучения для проекта MOEXScanner. Схема включает этапы от загрузки данных до интерпретации моделей.

---

## 1. Модуль: Загрузка и предобработка данных (Data Loading)
**Файл:** `ML/01_data_loading.ipynb`

### Входные данные
- **Источник:** Локальные CSV файлы в структуре папок `data/MOEX_DATA/{Тикер}/{Таймфрейм}/`.
- **Формат:** OHLCV (Open, High, Low, Close, Volume), поля `begin`/`end` для времени.

### Процессы
1. **Поиск данных:** Скрипт сканирует директории для заданного списка тикеров (SBER, GAZP, LKOH и др.).
2. **Парсинг дат:** Преобразование строковых полей `begin`/`end` в `datetime`.
3. **Расчет доходностей:**
   - Вычисляются логарифмические доходности: `log_return = log(Price_t / Price_{t-1})`.
   - Используются цены закрытия (`close`).
4. **Очистка:** Удаление пропусков (NaN), возникающих из-за лагов (shift).

### Выходные данные
- **Файлы:** `data/processed/{ticker}_ohlcv_returns.parquet`
- **Состав:** Базовые свечные данные + колонка `log_return`.

## 2. Модуль: Генерация признаков (Feature Engineering)
**Папка:** `ML/02_feature_engineering/`

### 2.1 Признаки волатильности (Volatility Features)
**Файл:** `ML/02_feature_engineering/01_volatility_features.ipynb`
> **Примечание:** В данном модуле планируется пересмотр набора фич (по запросу пользователя). Текущая реализация описана ниже.

**Вход:** `data/processed/{ticker}_ohlcv_returns.parquet`

**Процессы (расчет метрик):**
1. **Realized Volatility:** Скользящее стандартное отклонение `log_return` (окна: 10, 30, 60). Масштабируется на `sqrt(252)`.
2. **EWMA Volatility:** Экспоненциально взвешенное скользящее среднее стандартное отклонение (спаны: 10, 30, 60).
3. **Parkinson Volatility:** Оценка на основе размаха High-Low. Более эффективна для внутридневных данных.
4. **Garman-Klass Volatility:** Оценка на основе OHLC. Учитывает открытия и закрытия, более точная оценка, чем Parkinson.
5. **Directional Volatility:** (Опционально в коде) Раздельная волатильность для растущих и падающих свечей.

**Выход:** `data/features/{ticker}_volatility_features.parquet` (промежуточный датасет).

### 2.2 Целевые переменные (Targets)
**Файл:** `ML/02_feature_engineering/05_targets.ipynb`

**Вход:** Датасет с признаками (или базовый `ohlcv_returns`).

**Процессы:**
1. **Target Volatility:** Реализованная волатильность, сдвинутая в будущее на горизонт прогноза (1, 5, 10 дней). `shift(-horizon)`.
2. **Spike Flag:** Бинарный признак всплеска волатильности (1, если будущая доходность отклоняется более чем на 2 сигмы от скользящего среднего).
3. **Quantiles:** Квантили (16%, 50%, 84%) будущего распределения доходностей (для QR моделей).
4. **Direction:** Направление движения цены (1 - рост, 0 - падение) на горизонте прогноза.

**Выход:** `data/features/{ticker}_with_targets.parquet` — итоговый датасет для обучения.

*(Также в папке присутствуют файлы для генерации признаков объема, рыночных и трендовых факторов, которые интегрируются в общий пайплайн аналогичным образом).*

## 3. Модуль: Моделирование (Modeling)
**Папка:** `ML/03_models/`

### 3.1 Базовые модели (Baseline)
**Файл:** `ML/03_models/01_baseline_models.ipynb`

**Вход:** `data/features/{ticker}_with_targets.parquet`

**Процессы:**
1. **Naive Forecast:** Прогноз на завтра равен значению волатильности сегодня. Используется как нижняя планка качества.
2. **EWMA Forecast:** Прогноз равен значению экспоненциальной скользящей средней.
3. **Оценка:** Расчет метрик MAE (Mean Absolute Error) и RMSE (Root Mean Squared Error) на отложенной выборке или всем датасете.

**Выход:**
- Файлы прогнозов: `data/models/{ticker}_baseline_forecasts.parquet`
- Метрики: `data/models/{ticker}_baseline_metrics.csv`

*(Другие модели: GARCH, LightGBM Quantile, Ensemble - реализуют более сложные алгоритмы прогнозирования условной дисперсии).*

## 5. Модуль: Интерпретируемость (Explainability)
**Папка:** `ML/05_explainability/` (исследовательские notebooks)  
**Production модули:** `ML/explainability/`

### 5.1 Production модули объяснимости

#### 5.1.1 ShapExplainer (`explainability/shap_wrapper.py`)

**Назначение:** Обертка для SHAP TreeExplainer с оптимизацией производительности.

**Ключевые особенности:**
- Ленивая инициализация: TreeExplainer создается один раз при первом использовании
- Использует медианную модель (q50) для объяснений
- Поддерживает фоновый датасет для более точного base_value
- Может работать без фоновых данных (с предупреждением)

**Основные методы:**
- `__init__(model, background_data, feature_names)` - инициализация с обученной LightGBM моделью
- `explain_local(features_vector)` - вычисление SHAP значений для одного вектора признаков
  - Возвращает: `shap_values`, `base_value`, `feature_names`, `prediction`
- `format_explanation(explanation, top_n)` - форматирование в список словарей
  - Возвращает: `[{'feature': 'parkinson_vol', 'value': 0.05, 'contribution': 0.02}, ...]`
  - Отсортировано по абсолютной величине вклада
- `explain_and_format(features_vector, top_n)` - объединенный метод

**Входные данные:**
- Обученная LightGBM модель (`lgb.Booster`)
- Фоновый датасет (опционально, 50-100 образцов из X_train)
- Вектор признаков для объяснения (pd.Series, pd.DataFrame или np.ndarray)

**Выходные данные:**
- Словарь с SHAP значениями, базовым значением и прогнозом
- Отформатированный список словарей с вкладом каждого признака

---

#### 5.1.2 ExplanationGenerator (`explainability/text_generator.py`)

**Назначение:** Генератор текстовых объяснений на русском языке.

**Ключевые компоненты:**
- `FEATURE_DESCRIPTIONS` - словарь переводов технических названий признаков на русский
  - Примеры: `'parkinson_vol_10d'` → `'внутридневного размаха цен (10 дней)'`
  - Покрывает все ~66 признаков модели

**Основные методы:**
- `generate_text(formatted_explanation, prediction_value, top_drivers=3)` - генерация текста
  - Разделяет признаки на драйверы (положительный вклад) и стабилизаторы (отрицательный)
  - Формирует предложение: "Прогноз волатильности (X%) сформирован в основном за счет Y и Z."
- `generate_detailed_text(...)` - подробное объяснение с детализацией вклада каждого признака
- `_split_drivers_stabilizers(...)` - вспомогательный метод для разделения признаков

**Входные данные:**
- Отформатированное объяснение из `ShapExplainer.format_explanation()`
- Значение прогноза (q50)

**Выходные данные:**
- Текстовое объяснение на русском языке
- Пример: "Прогноз волатильности (15.00%) сформирован в основном за счет внутридневного размаха цен (10 дней) и инерции тренда (20 дней). Снижению волатильности способствуют аномального объема (20 дней) и отклонения от скользящей средней (50 дней)."

### 5.2 Интеграция в inference pipeline

**Модуль:** `03_models/inference.py`

**Изменения в `GlobalQuantileModel`:**
- Добавлены атрибуты: `self.explainer` (ShapExplainer) и `self.text_generator` (ExplanationGenerator)
- Метод `_init_explainer(background_data)` - ленивая инициализация SHAP explainer
- Метод `predict()` расширен параметрами:
  - `include_explanation: bool = False` - включить объяснения
  - `background_data: Optional[pd.DataFrame] = None` - фоновый датасет

**Логика работы:**
1. Если `include_explanation=False` → возвращает DataFrame (обратная совместимость)
2. Если `include_explanation=True`:
   - Инициализирует explainer (если еще не инициализирован)
   - Вычисляет объяснения для каждой строки входных данных
   - Генерирует текстовые объяснения
   - Возвращает словарь с `forecast` и `explanation`

**Формат ответа:**
```python
{
    'forecast': DataFrame,  # Колонки: pred_q16, pred_q50, pred_q84, interval_width
    'explanation': {
        'text': str | List[str],  # Текст для одной строки или список для нескольких
        'raw_data': List[Dict] | List[List[Dict]]  # Сырые данные для визуализации
    }
}
```

**Обработка ошибок:**
- Обернуто в `try-except` блок
- При ошибке объяснений возвращаются только прогнозы (не ломает production)
- Предупреждения вместо исключений

### 5.3 Тестирование

**Скрипт:** `scripts/test_explanation.py`

**Функциональность:**
1. Загрузка модели и данных SBER
2. Прогноз с объяснениями для последней строки
3. Валидация структуры JSON ответа
4. Вывод текстового объяснения в консоль
5. Сохранение JSON в файл для проверки фронтендом
6. Тестирование edge cases (NaN, нули, пустые данные)

**Запуск:**
```bash
python scripts/test_explanation.py
```

**Выходные данные:**
- Консольный вывод с валидацией
- Файл `scripts/test_explanation_output.json` с полной JSON структурой
